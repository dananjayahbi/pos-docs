## Task 72: Create Employee Payslip ViewSet

### Overview
Create a read-only ViewSet using Django REST Framework's `ReadOnlyModelViewSet` to provide employee self-service access to their payslips. This ViewSet implements secure access controls ensuring employees can only view their own payslips, never those of other employees.

### Dependencies
- `PayslipSerializer` from Task 69 must exist
- DRF framework installed and configured
- User authentication system in place
- Employee model linked to User model

### Instructions

1. **Create employee views module**
   - Navigate to `apps/payslip/views/` directory
   - Create `employee.py` file
   - This module handles employee-facing API endpoints

2. **Import required dependencies**
   - Import `ReadOnlyModelViewSet` from DRF
   - Import permission classes (`IsAuthenticated`)
   - Import `Payslip` model
   - Import `PayslipSerializer`
   - Import response classes for file handling

3. **Define EmployeePayslipViewSet class**
   - Inherit from `ReadOnlyModelViewSet`
   - This base class provides `list()` and `retrieve()` automatically
   - No create, update, or delete operations needed

4. **Configure ViewSet attributes**
   - Set `serializer_class` to `PayslipSerializer`
   - Set `permission_classes` to require authentication
   - Set `lookup_field` to primary key (default behavior)

5. **Override get_queryset() method**
   - Filter payslips by `request.user.employee`
   - Order by payroll period start date (descending)
   - Include related data with `select_related()` and `prefetch_related()`
   - This ensures employees only see their own data

6. **Configure pagination settings**
   - Use default REST framework pagination
   - Typically 10-20 payslips per page
   - Employee can navigate through historical payslips

### ViewSet Inheritance Benefits

| Method | Provided By | Purpose |
|--------|-------------|---------|
| `list()` | ReadOnlyModelViewSet | List all payslips for employee |
| `retrieve()` | ReadOnlyModelViewSet | Get single payslip details |
| `get_queryset()` | Custom override | Filter to employee's payslips only |

### Security Principles

**Authentication Required**
- All endpoints require valid authentication token
- Unauthenticated requests receive 401 Unauthorized
- Token identifies the requesting employee

**Authorization by QuerySet Filtering**
- QuerySet filtered to `request.user.employee`
- If employee tries to access another's payslip by ID, returns 404
- No indication other payslips exist
- Prevents information disclosure

**Read-Only Access**
- Employees cannot modify payslips
- Cannot delete or create payslips
- Enforced at ViewSet level
- Only HR/Payroll users can modify through admin

### Expected Behavior

**List Endpoint (GET /api/v1/payslips/my/)**
- Returns paginated list of employee's payslips
- Ordered newest first
- Shows summary information
- Each item contains slip_number, period, status

**Detail Endpoint (GET /api/v1/payslips/my/{id}/)**
- Returns full payslip details
- Includes nested earnings and deductions
- Shows YTD calculations
- Contains employer contributions

**Invalid Access Attempts**
- Accessing other employee's payslip ID returns 404
- No error message reveals payslip exists
- Logged for security monitoring
- Consistent with privacy requirements

### QuerySet Optimization

**Select Related**
- Employee profile data
- Payroll period information
- Generated by user information
- Reduces database queries

**Prefetch Related**
- Payslip earnings (many-to-many or reverse FK)
- Payslip deductions (many-to-many or reverse FK)
- Employer contributions
- Efficient loading of related collections

**Ordering Strategy**
- Order by `payroll_period__start_date DESC`
- Most recent payslips appear first
- Consistent sorting for pagination
- Index on start_date for performance

### Expected Outcome
- ViewSet handles employee payslip requests
- Secure access control implemented
- Optimized database queries
- Foundation for custom actions

## Task 75: Add Download PDF Endpoint

### Overview
Implement a custom action to download the generated payslip PDF file. This endpoint streams the PDF file to the client using Django's `FileResponse`, sets appropriate headers for download, and triggers download tracking logic to record access.

### Dependencies
- Task 72 (EmployeePayslipViewSet) completed
- Task 74 (retrieve action) working
- PDF files generated and stored (from Group C)
- File storage system configured

### Instructions

1. **Define custom download action**
   - Use `@action` decorator with `detail=True`
   - Set HTTP methods to `['get']`
   - Specify URL path as 'download'
   - Results in URL: /api/v1/payslips/my/{id}/download/

2. **Import required classes**
   - Import `FileResponse` from Django HTTP
   - Import `action` decorator from DRF
   - Import file storage utilities
   - Import mimetypes module

3. **Implement download method**
   - Accept request and pk parameters
   - Retrieve payslip using `get_object()`
   - Verify PDF file exists
   - Open file for reading in binary mode

4. **Configure FileResponse**
   - Create FileResponse with file object
   - Set Content-Type to `application/pdf`
   - Set Content-Disposition to `attachment`
   - Include filename in header

5. **Apply download tracking**
   - Call download tracking logic (Task 77)
   - Update download_count
   - Set last_downloaded_at timestamp
   - Update payslip status if applicable

6. **Handle file not found errors**
   - Check if PDF file exists before opening

   - Content-Type: application/pdf
   - Content-Disposition: attachment; filename="slip_number.pdf"

   - Cache-Control: no-cache (sensitive financial data)

### FileResponse Streaming

**Streaming Benefits**
- Large PDF files don't load into memory
- FileResponse reads file in chunks
- Efficient for multiple concurrent downloads
- Reduces server memory pressure

**Chunk-Based Delivery**
- Default chunk size is 4KB
- Django handles chunk iteration automatically
- Browser receives chunks progressively
- Download progress indicators work correctly

**File Handle Management**
- FileResponse closes file automatically after sending
- No manual file.close() needed
- Prevents resource leaks
- Safe for concurrent requests

### Response Headers Explanation

**Content-Type: application/pdf**
- Identifies response as PDF document
- Browser knows how to handle content
- Opens in PDF viewer or downloads
- Critical for proper display

**Content-Disposition: attachment; filename="..."**
- `attachment` triggers download dialog
- Alternative: `inline` opens in browser
- `filename` suggests save name
- Browser uses this for default filename

**Content-Length: {bytes}**
- Total file size in bytes
- Enables download progress indicators
- Browser can show "X of Y MB downloaded"
- FileResponse sets automatically if available

**Cache-Control: no-cache, private**
- Prevents caching of sensitive data
- `no-cache` requires revalidation
- `private` indicates user-specific content
- Important for financial documents

## Task 76: Add View Tracking Logic

### Overview
Implement tracking logic to record when employees view their payslips. This includes incrementing a view counter, setting the first view timestamp, and updating the payslip status to reflect that it has been viewed. View tracking provides valuable audit trail and delivery confirmation.

### Dependencies
- Payslip model has view tracking fields (Task 40)
- Task 74 (retrieve action) implemented
- Django timezone utilities available

### Instructions

1. **Identify tracking trigger point**
   - View tracking occurs in `retrieve()` method
   - Triggered when employee accesses payslip detail
   - Before serialization and response
   - After successful authorization

2. **Implement view tracking method**
   - Create `track_view()` method on ViewSet
   - Accept payslip instance as parameter
   - Update view-related fields
   - Save changes to database

3. **Increment view count**
   - Access current `view_count` value
   - Increment by 1
   - Accumulates across all views
   - Never resets

4. **Set first view timestamp**
   - Check if `first_viewed_at` is None/null
   - If null, set to `timezone.now()`
   - If already set, leave unchanged
   - Captures first access time only

5. **Update payslip status**
   - Check current status value
   - If status is `SENT`, update to `VIEWED`
   - Indicates employee has seen payslip
   - Status progression tracked

6. **Persist changes**
   - Call `payslip.save()` to persist
   - Use `update_fields` parameter for efficiency
   - Only update modified fields
   - Minimizes database overhead

7. **Integrate with retrieve action**
   - Call `track_view()` in retrieve() method
   - After successful authorization
   - Before returning response
   - Transparent to employee

### View Tracking Fields

| Field | Type | Purpose |
|-------|------|---------|
| `view_count` | Integer | Total number of views |
| `first_viewed_at` | DateTime | When first viewed |
| `last_viewed_at` | DateTime | When last viewed (optional) |

### View Tracking Workflow

1. **Employee requests payslip detail**
2. **Authentication and authorization verified**
3. **Payslip instance retrieved**
4. **Check first_viewed_at field**
   - If null: Set to current timestamp
   - If set: Leave unchanged
5. **Increment view_count by 1**
6. **Update status if SENT**
   - Change status from SENT to VIEWED
   - Marks delivery confirmation
7. **Save changes to database**
8. **Serialize and return response**

### Status Transition Logic

**GENERATED → SENT**
- Occurs when email sent (Task 62)
- Not part of view tracking
- Separate email delivery process

**SENT → VIEWED**
- Occurs on first view
- Triggered by view tracking
- Confirms employee accessed payslip
- Important for delivery verification

**VIEWED → DOWNLOADED**
- Occurs on first download
- Handled by download tracking (Task 77)
- Separate from view tracking

### Overview

### DRF Router Concepts

**DefaultRouter vs SimpleRouter**
- `DefaultRouter` includes API root view
- Shows available endpoints at `/api/v1/payslips/`
- SimpleRouter omits root view
- DefaultRouter recommended for browsable API

**Router Registration**
- Router connects URL patterns to ViewSet
- Generates standard REST endpoints automatically
- Handles list, detail, create, update, delete
- Respects ViewSet type (ReadOnly = no create/update/delete)

**Basename Parameter**
- Used for URL name generation
- Format: `{basename}-list`, `{basename}-detail`
- Custom actions: `{basename}-{action_name}`
- Important for reverse() function

**List Endpoint**
- URL: `/api/v1/payslips/my/`

- Action: `list()`
- Name: `my-payslips-list`
- Returns: Paginated list of employee's payslips

**Detail Endpoint**
- URL: `/api/v1/payslips/my/{id}/`
- HTTP Method: GET
- Action: `retrieve()`
- Name: `my-payslips-detail`
- Returns: Single payslip with full details

**Download Action**
- URL: `/api/v1/payslips/my/{id}/download/`
- HTTP Method: GET
- Action: `download()`
- Name: `my-payslips-download`
- Returns: PDF file stream

**Other Actions**
- Any additional custom actions automatically routed
- URL pattern: `{prefix}/{id}/{action_name}/`
- HTTP methods defined in action decorator
- Named: `{basename}-{action_name}`
