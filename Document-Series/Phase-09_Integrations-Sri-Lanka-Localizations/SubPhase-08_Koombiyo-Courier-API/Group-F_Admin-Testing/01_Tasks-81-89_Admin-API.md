## Task 81: Create Waybill Admin

### Overview
Create a comprehensive Django admin interface for the Waybill model. This admin provides staff users with the ability to view, search, filter, and manage waybills generated through Koombiyo. Include list display with key fields, filtering capabilities, search functionality, and read-only fields for API-generated data.

### Dependencies
- Task 80: Create COD Reconciliation (from Group E)
- Waybill model from Task 16
- Django admin infrastructure

### Instructions

1. **Register Waybill model in admin**
   - Navigate to `backend/apps/shipping/admin.py`
   - Import Waybill model
   - Create WaybillAdmin class inheriting from admin.ModelAdmin
   - Register Waybill with custom admin class

2. **Configure list display**
   - Define `list_display` tuple with key fields
   - Include: order number (via FK), waybill_number, status, created_at
   - Add service_type and weight for quick overview
   - Include shipping cost and payment method

3. **Set up list filters**

6. **Set read-only fields**
   - Define `readonly_fields` tuple
   - Mark waybill_number as read-only (generated by API)
   - Mark tracking_url and pdf_url as read-only
   - Mark api_response as read-only (JSON from Koombiyo)

## Task 82: Create Waybill Actions

### Overview
Add custom admin actions for bulk operations on waybills. The primary action is bulk label printing, which allows staff to select multiple waybills and generate a combined PDF with all shipping labels. This streamlines the fulfillment process by eliminating the need to print labels individually.

### Dependencies
- Task 81: Create Waybill Admin
- PDF generation utilities

### Instructions

1. **Create bulk print labels action**
   - In `shipping/admin.py`, define `bulk_print_labels` function
   - Accept modeladmin, request, and queryset parameters
   - This function handles multiple selected waybills

2. **Validate waybill selection**
   - Check that at least one waybill is selected
   - Verify selected waybills have status appropriate for printing
   - Filter out waybills without generated labels (no pdf_url)
   - Show admin message if no valid waybills selected

3. **Collect PDF URLs from waybills**
   - Iterate through queryset
   - Extract pdf_url from each waybill
   - Create list of PDF URLs to merge
   - Handle cases where pdf_url is None or invalid

4. **Merge PDFs into single document**
   - Use PyPDF2 or reportlab to merge PDFs
   - If PDFs are URLs, download them first
   - Combine all label PDFs into one document
   - Handle errors gracefully (missing PDFs, network issues)

5. **Generate combined PDF response**
   - Create HttpResponse with PDF content type
   - Set filename as "waybill_labels_{timestamp}.pdf"
   - Add Content-Disposition header for download
   - Return PDF file to browser

6. **Add action to WaybillAdmin**
   - Add `actions` list to WaybillAdmin class
   - Include 'bulk_print_labels' action
   - Set short description for action dropdown

7. **Add error handling and messages**
   - Use admin messages to notify success/failure
   - Show count of labels printed
   - Display warnings for skipped waybills
   - Log errors for debugging

8. **Test bulk action**
   - Select multiple waybills in admin list view
   - Execute bulk print action from dropdown
   - Verify combined PDF downloads correctly
   - Check all labels included and properly formatted

## Task 86: Create Waybill API

### Overview
Create REST API endpoints for waybill management using Django REST Framework. This API provides programmatic access to waybill data for frontend applications, mobile apps, and external integrations. Implement ViewSets with serializers for list, retrieve, and create operations on waybills.

### Dependencies
- Task 81: Create Waybill Admin
- Waybill model from Task 16
- Django REST Framework setup

### Instructions

1. **Create API directory structure**
   - Navigate to `backend/apps/shipping/`
   - Create `api/` directory if not exists
   - Create `__init__.py` in api directory
   - Create files: `serializers.py`, `views.py`, `urls.py`

2. **Create Waybill serializer**
   - In `api/serializers.py`, create WaybillSerializer class
   - Inherit from serializers.ModelSerializer
   - Define Meta class with Waybill model

3. **Configure serializer fields**
   - Include all relevant waybill fields
   - Use SerializerMethodField for computed values
   - Add nested order serializer (read-only)
   - Include tracking_events as nested field

4. **Define read-only fields**
   - Mark waybill_number as read-only (API generated)
   - Mark tracking_url and pdf_url as read-only
   - Mark timestamps as read-only

5. **Create Waybill ViewSet**
   - In `api/views.py`, create WaybillViewSet class
   - Inherit from viewsets.ModelViewSet
   - Set queryset to Waybill.objects.all()
   - Set serializer_class to WaybillSerializer

6. **Configure ViewSet permissions**
   - Add permission_classes for authentication
   - Require IsAuthenticated for all actions
   - Consider tenant-based filtering

7. **Implement filtering**
   - Add filter_backends (DjangoFilterBackend, SearchFilter)
   - Define filterset_fields: status, created_at, payment_method
   - Define search_fields: waybill_number, order__order_number
